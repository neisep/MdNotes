# MdNotes — local markdown notes app (C# / Avalonia / MVVM)

## Context
Small Obsidian-like app for documenting things locally as `.md` files. Decisions made by the user:
- Split view: raw text editor + live rendered preview
- Features: folder tree, open/edit/save, **autosave**, **create/rename/delete notes & folders**,
  **full-text search**, **[[wikilinks]]**, **Mermaid diagrams**
- **No embedded browser** (the first version used WPF + WebView2; rejected as a dependency)
- **Cross-platform** (Windows, macOS, Linux) → Avalonia instead of WPF
- Go/Fyne and Rust were considered and rejected: Fyne needs a C compiler and cannot draw SVG text,
  and both would have meant rewriting the working services and tests.

## Stack
- .NET 10 (`net10.0`), nullable + implicit usings on
- `Avalonia` 12.1.2 + `Avalonia.Desktop` + `Avalonia.Themes.Fluent`, compiled bindings on
- `CommunityToolkit.Mvvm` 8.4.2 — `ObservableObject`, `[ObservableProperty]`, `[RelayCommand]`
- `Markdig` 1.3.2 — markdown → syntax tree (`UseAdvancedExtensions()` + custom wikilink extension)
- `Mermaider` 0.13.1 — Mermaid → SVG in pure .NET (no browser, no JavaScript)
- `Svg.Controls.Skia.Avalonia` 12.0.0.17 — draws the SVG (supports text)
- Tests: xunit v3 + `Avalonia.Headless.XUnit` (headless UI tests render real frames with Skia)

## Behaviour notes
- **Startup**: with no file argument the window opens, LastVaultPath is loaded if it exists, else
  PickFolder; cancelling closes. With a file argument the vault is *restored only if there is one*
  (`TryRestoreVault`, never prompts) and the file is opened with `OpenLooseFile`.
- **Loose files**: `MdNotes.exe <path>` opens a file from outside the vault. `EditorViewModel.IsLooseFile`
  (path not under `VaultService.RootPath`) forces `SaveMode` to `Manual`, which turns the autosave timer
  off and stops `Load`/`Close` saving implicitly; `EditorViewModel.FlushUnsavedAsync` asks before the editor
  moves on. The sidebar
  keeps the vault, and `ImportToVault` copies the buffer into it, leaving the original alone.
- **One process**: `SingleInstance` (named pipe, per user) hands a later launch's path to the running
  app, which opens another window. `AppSession` owns one vault/settings/dialog set for every window,
  so `MainViewModel` is `IDisposable` and detaches from `VaultChanged` when its window closes.
- **Vault identity has one owner**: the vault is process-wide, so `VaultService.RootPath` is the only
  copy of it - `MainViewModel.VaultPath`/`VaultName` read the service rather than storing it. `Open`
  returns false and stays silent for the vault it already has (every new window restores the last
  vault, and announcing that would reset the windows already showing it); a real switch raises
  `VaultOpened`, and every window resets its title, tree, search and undo from the one handler. A note
  left open elsewhere survives the switch and becomes a loose file, which the status bar now says.
- **Theme has one owner too**: `ISettingsService` notifies, `AppSession` applies the variant once for
  the application, and `MainViewModel.ThemeMode` reads the setting. One variant, one persisted value,
  no window holding a copy that the others overrule.
- **The tree is reconciled, not rebuilt**: `RefreshTree` diffs `Tree` against the vault's entries by
  path (`TreeNodeViewModel.Reconcile`) instead of clearing it, so a row that is still there is the same
  object afterwards and keeps whatever the sidebar hung on it. Nothing has to be captured before a
  refresh and replayed after, and a new piece of per-row state costs nothing - which matters because
  the refresh rides a 300 ms debounce off *any* filesystem event. Identity is `(FullPath, IsFolder)`
  compared ordinally: a rename, including a case-only one, is a new row, not an old row holding a path
  the disk no longer has. Selection has one owner too - `SelectedNode`, bound to `TreeView.SelectedItem`
  - and the drop highlight is the view's own, set on the row control rather than written back onto it.
- **File association**: `WindowsFileAssociationService` writes the HKCU ProgId, OpenWithProgids and
  RegisteredApplications capabilities, calls SHChangeNotify, then opens Settings > Default apps.
  Windows guards the real default behind a hashed UserChoice key, so the last click is the user's.
- **Theme**: ribbon button cycles System → Light → Dark → System; persisted and applied on startup.
  Application-wide: every window follows, whichever one the button was pressed in.
- **Diagram colours**: `MarkdownView` resolves `MdSurface`/`MdText` from the theme at render time and
  passes them down as a `DiagramPalette`, which is also the cache key. Editing `Themes/Palette.axaml`
  moves diagrams with everything else. Mermaider's own line/accent/series colours are still its.
- **View mode**: Edit / Split / Reading toggled from PaneHeader icon buttons or `Ctrl+E` (Edit ↔ Reading;
  Split → Reading); persisted and applied on startup.
- **Sidebar**: toggled via ribbon Files button; hidden shows full width for editor/preview.
- **Quick switcher**: `Ctrl+O` opens search box; Up/Down/Enter/Escape to navigate and open note; Escape or
  click scrim closes; no match + non-empty query shows create item.
- **Autosave**: three modes in `ISettingsService.AutoSave`, chosen in the settings overlay. `AfterDelay`
  (default) restarts a timer of `AutoSaveDelayMs` (default 750, clamped to 0.1-300 s) on every text change
  → `VaultService.Write`. `OnFocusChange` drops the timer and relies on `SaveImplicitly`. `Manual` writes
  only on Ctrl+S, and `FlushUnsavedAsync` asks before the editor moves on — answering no abandons the
  draft, which is the point of the mode. `SaveMode` is read at the point of use, so a change in the panel
  applies from the next keystroke. Loose files are always `Manual`, whatever the setting says.
- **New note template**: `ISettingsService.NewNoteTemplatePath` names a note relative to the vault root.
  `NoteTemplateService.ContentFor` reads it and `NoteTemplate.Apply` fills `{{title}}`/`{{date}}`/`{{time}}`
  (each may carry a `:format`); anything else is left verbatim, so a template can carry another tool's
  syntax unharmed. It reaches the three paths that create a note from a name the user gave — `NewNote`,
  the quick switcher's Create row and the `OpenWikiLink` fallback — through the single
  `MainViewModel.CreateFromTemplate`; `ImportToVault` passes its own buffer instead, because the content
  already exists. Unconfigured, no vault, outside the vault, missing, unreadable, or creating the template
  file itself all resolve to `""`: the note is created blank and nothing is reported, because a template
  problem must never block a note. The settings panel's status line is where that shows instead.
- **Exclusions**: `.mdnotesignore` at the vault root, compiled by `VaultIgnore` and applied by
  `VaultService` at its three enumeration points — `GetTree`, `EnumerateNotes` and `EnumerateFolders` —
  so search, replace, the quick switcher, the folder-scope list and both wikilink lookups inherit it
  without knowing it exists. Excluded folders are pruned before they are descended into, which is the
  whole performance claim. `EnumerateNotes` is hand-rolled rather than `SearchOption.AllDirectories`
  precisely because that overload cannot be stopped from descending. Ordering happens **before**
  filtering: `ReadEntries` is unfiltered and is what `.order` is written from, so an excluded entry
  keeps its line and its place when a sibling is dragged past it, and `MoveTo` translates the sidebar's
  visible index into an index over every sibling on disk. The compiled list is cached against a stamp
  of the files' write time and length, re-checked per enumeration, because `NotifyFilters.LastWrite` on
  the main watcher would fire on every autosave; a second watcher filtered to the two file names covers
  content edits. `RefreshExclusions` deliberately raises the existing `VaultChanged`, so a change made
  in one window's settings panel rebuilds the tree in every window. Creating a note or folder the list
  would hide is refused at the vault boundary; renaming something already excluded stays legal.
- **Images**: `![alt](path)` resolves relative to the note (`MarkdownView.BaseDirectory` =
  `EditorViewModel.CurrentDirectory`) and must then land under `MarkdownView.ContentRoot` — the vault for a
  note inside one, the note's own folder for a loose file, which has no vault to be contained by. A path
  that climbs out (`![](../../../../etc/hosts)`) renders as `[image: alt]` instead, the same as a missing
  file: `NoteImagePath.Resolve` normalises with `GetFullPath` **before** the `PathScope.IsSameOrUnder`
  prefix test, for the reason `NoteTemplateService` spells out. Notes are files the user already owns, so
  this is not a privilege boundary — it is the rule every other path site observes, applied at the one
  that skipped it, and it matters because a vault may be synced or shared. Decoded bitmaps are owned by
  the static `ImageCache`, keyed by path plus write stamp: the preview is rebuilt whole on the 250 ms
  timer, so without it every keystroke re-read and re-decoded every image on the render pass, and the
  bitmaps it made had no owner at all. An image edited outside the app is decoded again rather than
  served stale.
- **Wikilink click**: resolve `<Target>.md` anywhere in vault (case-insensitive by filename); if absent,
  fall back to a *folder* of that name, and only then create the note in the vault root and open it.
  http(s)/mailto links open via the OS launcher.
- **Folder links**: a trailing `/` makes the target a folder — `[[Projects/]]`, `[[Work/Projects/]]`,
  `[[Projects/|the project]]`. `FindFolderByName` matches a bare name against folder names anywhere in
  the vault and a name with separators against the vault-relative path, exact before accent-folded, and
  never returns a dot-folder or anything inside one. Clicking reveals the folder: `SelectPath` opens its
  ancestors and selects it, `OpenWikiLink` expands the folder itself, and the editor is untouched because
  `OnSelectedNodeChanged` already returns early for a folder. A missing folder is created at the root, as
  a missing note is — but only a plain name: a path that is not there is an error, not four new folders.
  The link carries a folder glyph in the preview, inside the link span so it is clickable with the text.
- **Mermaid**: fenced ```mermaid block → Mermaider SVG (colours follow light/dark theme) → Image.
  Diagram errors are shown in place, never swallowed.
- **Manual order**: a folder is alphabetical until something is moved in it; the first move writes every
  sibling's key to its `.order` file, so order is explicit rather than inferred. `VaultService.Rename`
  rewrites the key in place, which is what makes a manual position survive a rename. Entries the file does
  not list sort last, keeping the alphabetical folders-then-notes order, so an unlisted new note appears at
  the bottom rather than jumping. `MoveTo` is the single primitive behind both `Alt+↑`/`Alt+↓` and the drag:
  its index counts the destination's children *after* the entry is removed, and is clamped.
- **Drag & drop**: `Sidebar` hit-tests `Border#PART_LayoutRoot` (the row, excluding expanded children) and
  measures how far down it the pointer is; that is all the view decides. `VaultWorkspaceViewModel.
  PositionIn` reads the fraction - a folder's middle half drops *into* it, otherwise the nearer edge decides
  before/after - and `ResolveDrop` owns the index maths, returning null for a drop that is impossible (onto
  itself, into its own subtree) or pointless, which is what greys the drop out.
- **Search**: non-empty query swaps the tree for a results list; clicking a hit opens the note.
- **Search & replace**: `Ctrl+Shift+H` (or the sidebar button / tree menu) opens a modal overlay seeded
  with the sidebar query, scoped to the selected folder when one is selected. Preview and apply share
  `MatchFinder`, so what is written is what was shown. Notes and individual matches are ticked
  independently; exclusions are remembered as (path, offset) and reapplied after every rescan, so
  refining the replacement text does not discard them. Because the overlay is modal, the editor is
  flushed once when it opens and reloaded afterwards from disk — otherwise the autosave would write the
  stale buffer back over the replacement. In manual mode the replace acts on what is on disk, so the
  unsaved buffer is the user's call first. A note whose text moved since the scan is skipped
  whole rather than partially rewritten. Undo is one step, in memory, dropped on the next replace or a
  vault switch.
- **External changes**: watcher refreshes the tree (debounced); does not reload the open note's text.
- **Errors**: services throw descriptive exceptions; commands catch only at the VM boundary
  (`DialogGuard.Guard` / `GuardAsync` / `TryAsync`) and surface via `IDialogService.ShowErrorAsync`.
- **Shell and workspace**: a window is two view models. `MainViewModel` is the shell — view mode, theme,
  sidebar, title, settings — and `VaultWorkspaceViewModel` is the vault — tree, selection, CRUD,
  navigation, sidebar search. A feature about notes lands in the workspace and never touches the shell.
  `Sidebar.axaml` binds the workspace; everything else binds the window and reaches across with a
  `Workspace.` prefix. The editor stays on the shell, because the open note belongs to the window and
  outlives a vault switch as a loose file.
- **Delete**: confirm dialog; folders deleted recursively.

### 2026-09-18 (exclude files and folders from every indexer)

A real ignore list, not a display filter (forum.obsidian.md/t/52025, 347 likes — #29 and the top
unimplemented `win` in `docs/obsidian-feature-requests.html`). `.mdnotesignore` at the vault root, a
gitignore subset, edited from the settings panel; what it names is gone from the sidebar, search,

All file-system enumeration was already in one class, so the feature is three call sites in
`VaultService` plus a matcher. The care went into the two places filtering would have quietly broken
something. `MoveTo` calls the child reader only to feed `FolderOrderFile.Save`, which prunes by
construction: had the filtered reader been used, one drag in a folder with an excluded sibling would
have deleted that sibling's line, and un-excluding it later would have dropped it to the bottom of its
folder for good. So the reader is split — `ReadEntries` orders and does not filter (that is what

the order the rules were written in, and a re-included file under a pruned folder cannot be found

that is exactly the risk in the opt-in `.gitignore` switch — `*` plus `!src/` means "keep src" to git

the index now agree for the first time. `ReplaceService.IsHidden`, which compensated for exactly this,
is gone, and its `IsUnder` was a byte-for-byte copy of `PathScope.IsSameOrUnder`.

Decided rather than discovered: a note already open when its folder becomes excluded stays open and
simply loses its row — there may be unsaved text in it — which cost `SelectIfVisible` on the one path
(`RenameAsync`) that would otherwise have thrown into an error dialog. And creating something the list
would hide is refused at the vault boundary, beside `ValidateName`, because a note the sidebar, search
and the quick switcher all behave as if nonexistent is worse than a refusal. The settings card now
scrolls, with Done pinned outside the scroller, and Escape and the scrim move focus to Done first so a
list someone has just typed is not thrown away by the quickest way of closing the panel.

### 2026-09-18 (one owner for what is in the vault)
Finding F2 from `docs/architecture-review.html`. Four code paths each walked the vault from scratch on
demand - the sidebar tree, the quick switcher, the exclusion panel's note count, and both searches -
and the highest-frequency one had no debounce at all: `Sidebar.axaml` binds the search box with the
default per-keystroke trigger, and `SearchService.Search` reads the content of every note, so typing
five characters read the whole vault five times on the UI thread. The deeper problem was that there
was nowhere to put an index: each path owned its own traversal, so caching meant changing four things
and any future question about the vault would have added a fifth walk.

`Services/VaultWalk.cs` is now the only code that reads a vault folder off the disk. One walk answers
the tree, the note list and the folder list, because the three were always the same set seen three
ways - same `*.md` filter, same dot-folder rule, same exclusion test - which is how they had come to
disagree about `.git` in the first place. `VaultService` keeps the cache and hands out a
`VaultSnapshot`, reusing it while three things hold: same root, no structural change since, and the
very same `VaultIgnore` instance. That last one needs no new state, because `CurrentIgnore` already
returns the same instance until the ignore files move - which is why a `.mdnotesignore` edited behind
the app's back still reaches the next read, as it did before. The revision counter is the ABA guard:
nulling the field alone would let a reader that was mid-walk publish a tree built from pre-mutation
disk. The walk runs outside the lock, because the watcher thread takes the same lock once per event
and sees thousands during a build inside the vault.

Invalidation is the whole correctness argument. Every caller rebuilds the sidebar synchronously the
moment a mutation returns, long before the watcher reports it, so the six mutations invalidate before
returning - `Rename` and `MoveTo` in a `finally`, since a throw between their disk steps has already
changed the vault. `Write` deliberately does not: it is content only, autosave calls it on a timer,
and the main watcher does not listen to `LastWrite` either. `OnFsChanged` invalidates *before* raising
`VaultChanged`, never after, so a handler reading synchronously sees the change. A quiet event needs
nothing - the walk never descends into an excluded folder, so the snapshot cannot be holding it.

The sidebar search box is debounced 250 ms, the interval the other two keystroke-driven timers use.
`IsSearching` still flips on the keystroke, because it is the pane swap and the clear button rather
than a statement about results, and the previous hits stay up for that one beat instead of blinking
the list to empty, which reads as "no matches" mid-word. An empty query is never debounced and stops
a pending scan: the clear button and a vault switch both arrive that way, and a timer left armed would
search the new vault for the old vault's query. The quick switcher is deliberately left alone - with
the walk cached its per-keystroke cost is an in-memory flatten and sort, and its tests are plain

`IEnumerable<string> EnumerateNotes()` became `IReadOnlyList<string> GetNotes()`: once the answer is

`VaultIgnoreService` changed by that one name and nothing else, which was the point.

filters on names, not content.

### 2026-09-19 (the sidebar tree survives a refresh)

`docs/architecture-review.html` F6: the tree was discarded and rebuilt from disk on every change, so
every piece of per-row view state had to be captured before the rebuild and replayed after it.

`RefreshTree` now reconciles: `TreeNodeViewModel.Reconcile` matches the entries onto the rows already
there, removing what has gone, inserting what is new and `Move`-ing what has shifted, and recursing

`public static IDiagramRenderer? DiagramRenderer`, written by `App` at startup and by twelve test
files, plus a `static DiagramCache?` and a `static readonly ImageCache`. It was the one place the

### 2026-09-20 (the diagram cache owns its bitmaps outright)

`docs/architecture-review.html` F11, and it was real: `DiagramView` stored a bitmap the `Lru` owned and
drew it every frame, while the `Lru` disposed on eviction knowing nothing about what was on screen. The
review filed it at Medium confidence because reaching 32 live `(source, palette, pixelWidth)` keys needs
an unusual document. A test with the bound set to one settles it - two visible diagrams, the second's
rasterization evicts the first, and the next frame throws
`ObjectDisposedException: Ref<Avalonia.Platform.IBitmapImpl>` out of `DiagramView.Render`. That test now
guards the fix.

The fix is the first of the two shapes the review offered: the cache owns bitmaps outright and the view
borrows one for the length of a single draw. `DiagramView` keeps `_pixelWidth` - the cache *key* - and
nothing else; `CurrentBitmap()` asks the cache each time, and `Render` draws what it gets back. A key
owns nothing, so it cannot go stale the way a reference could. Avalonia takes its own reference on the
draw it records, so the bitmap surviving past `Render` is the compositor's business rather than the
view's - which is what makes borrowing for one call sufficient rather than merely shorter.

Nothing about the performance work this cache exists for changes: `Rasterize` still runs off the settle
timer rather than per resize frame, and it still warms the cache so the cost is not paid on the draw
path. A frame that follows an eviction pays one rasterization instead of drawing a disposed bitmap,
which is the LRU working.

`CurrentBitmap()` is a method rather than the old `Bitmap` property because a miss rasterizes, and a
property should not cost that.

**Found while fixing it, not fixed:** `ImageCache` has the same split. `InlineRenderer.AddImage` puts a
cache-owned `Bitmap` on an `Image` control's `Source`, which must hold it across frames, so the
borrow-per-draw answer is not available there - `Image.MeasureOverride` throws the same
`ObjectDisposedException` once eviction takes a bitmap that is still on screen (reproduced with
`new ImageCache(capacity: 1)`, two images, and a re-measure). Fixing it means choosing a different bound
- liveness-tracked entries, or a generational cache cleared one document behind - which is a design
decision rather than a translation of this one.

### 2026-09-21 (the vault-wide scans leave the UI thread)

Performance review finding 1: the sidebar search, the replace overlay's find and the tree walk all ran
on the UI thread off `DispatcherTimer` ticks, each reading every note in the vault - the walk included,
because with note titles on `VaultWalk.Of` is handed `_contents.Read` and opens every `.md` for its
head. The debounce decided how often that was paid, never how long it lasted.

Measured first, because the review said to and because the vault in use is four notes. `ScanBenchmark`
times the real services, and `VaultGenerator` writes a vault to drive the app against by hand - shaped
rather than filled (nested folders, sizes over an order of magnitude, declared titles on most, wikilinks,
tables, fences, Swedish text), because the per-note costs are the ones being measured and 2,000 identical
files measure one note 2,000 times. Both are gated on an env var, the way `AppIconGenerator` is.

The numbers said the review had ranked two findings the wrong way round. Median ms on a local SSD:

| notes | tree cold, titles on | titles off | tree re-walk | search cold | search warm | find warm |
|---|---|---|---|---|---|---|
| 2,000 | 261 | 15 | 98 | 388 | 154 | 128 |
| 5,000 | 785 | 42 | 1,060 | 2,206 | 1,196 | 1,457 |

Two and a half times the notes, eight to eleven times the work - except the titles-off row, which is
linear. That row is the control: it is the only one that never touches `NoteContentCache`. The cache
held 2,886 of 5,000 notes against its 8M-character budget, and past the budget a sequential pass over
every note evicts in exactly the order it is about to ask again, so every scan became a full re-read -
with `MinBy` picking each victim, making it quadratic. A cliff at roughly 3,000 notes, not a slope, and
nothing about threading would have moved it.

So finding 4 first. Recency is a `LinkedList` now rather than a stamp searched for with `MinBy`, which
makes each eviction O(1), and the budget is 32M characters - 64 MB of UTF-16, about twelve thousand
notes at the average measured. At 5,000 notes that is 324 ms warm search against 1,196, and the scaling
from 2,000 is linear again. The cliff still exists, four times further out; `HeldChars` against `Count`
is how the benchmark says a vault has gone over it, and it prints so.

Then finding 1. `ISearchService.Search` and `ReplaceService.Find` take a `CancellationToken` and check it
per note; both run under `Task.Run`, cancelled by the next keystroke. `NoteContentCache` is locked -
written failing, and it failed with "operations that change non-concurrent collections must have
exclusive access", because even a hit mutates. The disk read stays outside the lock on purpose: holding
it there would put the UI thread behind a background scan's OneDrive round trip, which is the freeze
being removed.

The tree split in two over one `Reconcile`. `RefreshTree` stays synchronous for the eight mutation
callers, which have just changed one entry and need the row back before they can select it.
`RefreshTreeAsync` is for the two cold walks - opening a vault, and the watcher - and a generation
counter means a walk finishing after a newer refresh drops its answer instead of putting the older vault
back on screen. `TreeReady` exposes the walk in flight, because `OnVaultOpened` runs off an event that
another window raises, so there is no call chain to await it through; `TryOpenInitialVaultAsync` and the
open command await it, since "the vault is open" is not true of a window still showing an empty sidebar.

One deliberate behaviour change: the replace overlay clears its results when the new ones arrive rather
than before the scan, so the list no longer blinks to empty and "No matches" only ever means no matches.
That makes it agree with the sidebar, which already worked that way.

Two things in the suite only broke once work could outlive the line that started it, and both were
latent rather than new. First, windows: `MainViewModel` is `IDisposable` and most tests never disposed
one, so a `_refreshTimer` tick landing after the test started a walk with no dispatcher left to finish
on. The windows are disposed now, `VaultWorkspaceViewModel.Dispose` closes the replace overlay as well,
and the overlay's own suite closes what it opens. Second, and the one that actually mattered:
`Avalonia.Headless` builds an application around the process-wide `Dispatcher.UIThread` per test class,
so two classes running at once had the second set itself up while the first still owned the dispatcher -
which failed the *next* class's setup, not the test that caused it, and pointed at innocent tests like
`MarkdownViewTests`. `DisableTestParallelization` in `TestAppBuilder.cs`; the suite is 19 s either way.

`NoteTitleDisplayTests.Saving_without_changing_the_title_leaves_the_tree_alone` was failing about one
full-suite run in four. Not caused by this change - it uses no view model and touches nothing that moved -
but exposed by it: `TempVault.Note` seeds behind the service's back and the watcher's `Created` event
lands a moment later, between the two `GetTree` calls the test compares. It now asks a second service
opened over the already-seeded folder, which is the pattern the F2 entry above already established for
exactly this.

Before: 4 runs, all green. After: 8 runs, 469 passing + 3 skipped, 0 warnings, no failures and no
cleanup failures.

Not done: the app itself has not been driven against a large vault by hand - the vault for it is at hand
(`VaultGenerator`) but the checks are owed. Findings 2 and 3 - `DisplayName` re-statting the ignore files
once per note, and the full folded copy of every note allocated per scan - are untouched, and they are
what the remaining 130 ms of warm search at 2,000 notes is mostly made of.
